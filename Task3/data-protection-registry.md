# Task3 — Классификация и защита данных

## Классификация

| Данные | Состояние | Чувствительность | Риск | Нужна защита потому что |
|--------|-----------|------------------|------|-------------------------|
| Учётные данные (пароль, токены) | rest + transit | secret | критический | захват аккаунта → доступ ко всем картам |
| ФИО, ДР, телефон, email | rest + transit + use | pii | высокий | 152-ФЗ, фишинг/утечка идентичности |
| Адрес, работа/учёба | rest + transit | pii | средний | профилирование, соц. инженерия |
| Диагноз, назначения, медкарта | rest + transit + use | special | критический | спецкатегория, репутационный удар |
| Результаты анализов | rest + transit | special | критический | медтайна, API лаборатории |
| Договор / паспортные реквизиты | rest + transit | pii | высокий | мошенничество, 152-ФЗ |
| Платёжные данные | transit (+token rest) | secret/pii | критический | фрод; PAN не хранить у себя |
| Кадры / ЗП | rest | pii | высокий | трудовой закон, инсайд |
| Логи, бэкапы с ПДн | rest | pii/special | высокий | скрытый канал утечки |
| Агрегированная аналитика | rest | internal/public | низкий | после обезличивания |

## Инструменты защиты (базовые + автоматизация)

| Класс | At rest | In transit | Контроль |
|-------|---------|------------|----------|
| secret | Vault, hash паролей, KMS | TLS 1.2+ | ротация секретов, запрет в git/логах |
| pii | TDE / column encrypt | TLS | RBAC, маскирование UI, DLP |
| special | KMS field/file encrypt | TLS + mTLS API | ABAC, audit каждого read, TTL/erase |
| платежи | только токен эквайера | TLS | PCI-scope вне периметра клиники |
| аналитика | шифрование lake | TLS | **только после anonymizer**, lineage |
| логи/бэкапы | encrypted backup | TLS | redact PII, отдельный ACL |

## Реестр средств

| Тип | Средство |
|-----|----------|
| ПО | TLS-терминация (Ingress), KMS, Vault, TDE Postgres, Presidio/DLP, DataHub+OpenLineage, SIEM/алерты, OIDC+RBAC/ABAC |
| Аппаратные / инфр. | HSM/облачный KMS, дисковое шифрование серверов, сегментация сети (VLAN), MFA-токены |
| Процессы | классификация при создании поля, CI-проверка тегов, регулярный access review, процедура erasure |

## Автоматизированный контроль

- CI: схемы с `class=pii|special` без `protection`/`retention` → fail.  
- Runtime: gateway режет поля по тегу и роли.  
- DLP на почте и выгрузках.  
- Audit → мониторинг (Victoria Metrics/SIEM) → алерт SecOps при аномалии.
